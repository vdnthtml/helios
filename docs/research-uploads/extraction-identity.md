# Helios Signal v0.1 — EXTRACTION / ENTITY RESOLUTION / NLP Audit

**Date verified:** 14 Nov 2026 (all star / licence / last-push claims below are from `browser.search` results run that day; where sources conflict the range is shown and the item is flagged)\
**Scope:** ONLY extraction / entity resolution / NLP. Python modular monolith, PostgreSQL + pgvector, staged extraction (cheap deterministic → structured model → evidence validation). ChatGPT's candidates under audit: GLiNER / Qwen-family as benchmark candidates (not locked), entity/event contracts, signal discovery/clustering.\
**Verdict key:** KEEP = adopt as ChatGPT proposed (with the stated pin) · KEEP+IMPROVE = keep, but change the tier/pin/contract · REPLACE = do not use as proposed; use the named alternative · BUILD = no off-the-shelf fit; build thin in-house on top of a named primitive · PARK = valid but not for v0.1.\
**Cost key:** $0 = free open-source, self-hosted, no API bill at Helios scale (electricity / laptop only). API cost is named separately where it applies.

> Licence warning that governs this whole layer: **code licence ≠ weight licence ≠ training-data licence.** Check the exact checkpoint's model card + LICENSE file before shipping. This bites GLiNER v0/v1 (CC-BY-NC), Qwen 3B/72B, NuExtract-2.0-4B, and every Fastino/Knowledgator checkpoint. See §5.

## 0. Executive verdict (read this first)

1. **ChatGPT's staged idea is right; its tier order is wrong.** Cheap deterministic → GLiNER → Qwen is the right shape, but GLiNER **v1 must not be the default** — use **GLiNER2 / GLiNER2.5 (Apache-2.0, schema-native)** as Tier 2, and keep GLiNER v1 `*-v2.1` Apache-2.0 checkpoints only as a fallback. Qwen must be **Qwen3 (Apache-2.0, 0.6–32B), never Qwen2.5-3B (research-only) or -72B (custom Qwen licence, 100M-MAU trigger)**.
2. **The single highest-leverage change for the whole layer is not a model — it is the contract.** LinkML YAML as source of truth → generated Pydantic v2 models → Postgres JSONB + pgvector, with every extraction carrying `span offsets + source char range + model + checkpoint + confidence + pipeline_version`. Without that, GLiNER, Qwen and LangExtract outputs cannot be compared, deduped, or refuted. Do this before any benchmark.
3. **Entity resolution: Splink 4 on DuckDB is the only KEEP.** Everything else in ER is a fallback, a stale toolkit, or a licence trap (Zingg AGPL, Tigramite GPLv3). Splink + deterministic blocking + LLM adjudication of the 0.60–0.90 band + human review is the v0.1 design.
4. **Do not build a causal engine in v0.1.** DoWhy + EconML are KEEP-as-research-gate only (identification + refutation, never a causal claim in product copy). Tigramite is PARK + GPL-quarantine. Causal-learn is the only discovery candidate, and only offline. The IWM verdict stands: influence is unidentifiable from observational network data (Shalizi & Thomas 2011; Eady 2023) — Helios sells *documented pathways + measured lead time*, not causation.
5. **ReLiK is the most dangerous pointer in the set — not because it is bad, but because it has no licence.** Do not ship it until the licence is resolved in writing. Its job (Wikidata entity linking + relation extraction) is real and otherwise unowned in this stack; the $0 workaround is GLiNER2 + a Wikidata alias gazetteer in Postgres.
6. **LangExtract is the surprise upgrade.** Google, Apache-2.0, \~39k stars, v1.7.2 (7 Nov 2026), precise source grounding (char offsets) + interactive visualisation. It is the best Tier-3 harness *if* it is pointed at a local Qwen3 via Ollama/vLLM — do not default it to Gemini (that re-introduces API cost + data-residency).

## 2. What ChatGPT got right, what it missed

**Right:** staged extraction (cheap → structured → validation); GLiNER + Qwen as *benchmark candidates, not locks*; entity/event contracts as the interface; keeping the LLM out of the cheap path.\
**Missed / needs fixing:**

- **GLiNER v1 vs GLiNER2/2.5 is a different product.** v1 is NER-only; GLiNER2/2.5 is schema-based NER + classification + structured extraction + relations in one forward pass, CPU-first, with a boundary-prediction architecture that removes the span-length ceiling. Benchmarking v1 in 2026 is benchmarking the past.
- **Qwen2.5 is the wrong default.** It is superseded (Qwen3, Apr 2025) and its 3B/72B sizes carry non-Apache licences. The audit's rule: *Qwen3-8B-Instruct, Apache-2.0, local*.
- **No grounding requirement.** ChatGPT's "evidence validation" stage needs a mechanism — LangExtract's char offsets are that mechanism. Without offsets, validation is a second LLM opinion, not evidence.
- **No ER design.** Entity resolution was implied, not specified. Splink + deterministic rules + adjudication bands (§3) is the missing design.
- **No licence-per-checkpoint discipline.** Four components in this layer have licence traps that are invisible at the repo level (GLiNER weights, Qwen sizes, NuExtract-4B, ReLiK absence). Add a CI licence gate.
- **Causal scope creep.** A DAG store does not need DoWhy+EconML+Tigramite in v0.1. It needs a *versioned DAG + refutation gate*. The rest is research debt.

## 3. Entity resolution — the v0.1 design (Splink + rules + adjudication)

1. **Source records first.** Every mention becomes a `person_source_record` / `org_source_record` (per-source identity). Golden `person`/`org` is a *reversible set of links*, never a mutated row. ER mistakes are fixed by link surgery.
2. **Deterministic blocking (Tier 0, Postgres).** Exact normalised name + (domain | handle | employer) → auto-link. UUIDv5 for source-keyed IDs (idempotent MERGE).
3. **Splink 4, DuckDB backend (Tier 1).** Fellegi–Sunter, EM-estimated m/u, blocking on name-trigram + employer + location. Runs in-process, no server. Re-run nightly; seconds at Helios scale.
4. **Bands (Tier 2).** ≥0.90 auto-link (never on name alone) · 0.60–0.90 → LLM adjudication (local Qwen3, JSON-schema, pair serialised Ditto-style) · 0.45–0.60 → human review queue · <0.45 discard. All bands logged with comparison vector + evidence.
5. **Embeddings as blocking, not deciding.** pgvector cosine proposes candidates for Splink; it never merges. (Embeddings cannot rank MIT > KTH or weigh 8,200 stars ≫ 82 — keep ordinal prestige in a separate scored table.)
6. **dedupe as labeller.** Use dedupe's active learning (label 30–50 pairs) to bootstrap Splink training data, not as the production linker.

## 6. $0 stack — total cost at Helios v0.1 scale

Every KEEP component above is $0 self-hosted. The only costs are: (a) electricity / a laptop or a $5–20/mo VPS if you want it always-on; (b) optional API spend if you point LangExtract at Gemini/OpenAI instead of local Qwen3 — **do not do this in v0.1**; (c) LlamaParse if you ignore the REPLACE verdict (don't). No component in the KEEP set has a paid tier that gates the v0.1 feature.

## 7. Highest-leverage changes, ranked

1. **Contract first (LinkML → Pydantic, §0.2).** One change, unlocks benchmarking, dedup, refutation, and every later tier.
2. **Promote GLiNER2.5 to Tier 2; demote GLiNER v1.** Schema-native, boundary prediction, Apache-2.0.
3. **Lock Qwen3-8B-Instruct (Apache-2.0, local) as the only structured LLM.** Kill Qwen2.5-3B from every doc/config.
4. **Adopt LangExtract as the grounding harness.** Char offsets or it didn't happen.
5. **Splink bands + reversible merges (§3).** ER correctness is the moat; a bad merge corrupts the graph silently.
6. **CI licence gate.** Fail the build if a checkpoint's LICENSE file is CC-BY-NC / Research-only / missing.
7. **Gold set before benchmarks (\~100 graded extraction examples, owner named).** Without it, every "X beats Y" claim in this audit and in vendor blogs is untestable on Helios data.
