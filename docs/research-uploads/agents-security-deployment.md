# Helios Signal v0.1 — Agents / Durable Jobs / APIs / Security / Deployment Audit

**Date:** 14 Nov 2026 (research run, IST) · **Scope:** ONLY agents, durable jobs, APIs, security, deployment — as tasked.\
**Architecture assumed:** Python modular monolith, PydanticAI with bounded workflows, DBOS or equivalent Postgres-backed durable jobs, owned web chat / signal feed / email briefing, RLS + OpenFGA/Keycloak, three scopes (shared public, tenant-private, derived customer), FastAPI + Postgres + pgvector + durable worker + object storage, no K8s/Kafka/graph cluster in v0.1.\
**Method:** `browser.search` + `browser.open` live checks, 14 Nov 2026. Stars are approximate snapshots and drift daily; where two secondary sources disagreed I give the range and the dated source. **Any star/date I could not verify live is marked UNVERIFIED — do not treat it as fact.** Repo URLs below are the canonical `github.com/<org>/<repo>` paths named in the sources; full URLs were taken verbatim from search results where available.\
**Licence shorthand:** MIT / Apache-2.0 = permissive OSI. SSPL / BSL / ELv2 / AGPL = source-available or copyleft — read the flag before building a hosted service on it.

## Verdict key

- **KEEP** — ChatGPT's choice stands for v0.1.
- **IMPROVE** — keep the direction, change how/when it is adopted.
- **REPLACE** — do not use this in v0.1; use the named alternative.
- **BUILD** — no off-the-shelf component; build a thin in-house layer.
- **DEFER** — correct later, wrong now (cost/complexity > v0.1 benefit).

## Executive verdict (one paragraph per layer)

1. **Agents — KEEP PydanticAI.** It is the right v0.1 bet: MIT, \~20k stars, v2.68.0 on 12 Nov 2026, typed contracts + DI + MCP/A2A + durable-execution hooks (Temporal/DBOS/Prefect/Restate). LangGraph is the only credible alternative and only if you need explicit graph state/checkpointing as the product's core. CrewAI/AutoGen are wrong for v0.1 (see below).
2. **Durable jobs — KEEP DBOS, with a named exit.** DBOS Transact (Python) is MIT, \~1.6k stars, v2.31.0 (25 Aug 2026), last commit 27 Oct 2026, and is the *only* option that adds durability as a library on the Postgres you already run — zero new infra. Its weaknesses are real: tiny community, proprietary Conductor UI (no free UI), v2.0 broke pre-2.0 workflow recovery. Mitigation: wrap it behind one `jobs.py` interface so Temporal/Hatchet can replace it without touching agents; do NOT adopt its Cloud/Conductor.
3. **APIs — KEEP FastAPI + LiteLLM Router (in-process first).** FastAPI \~105k stars, MIT, v0.162.2 (7 Nov 2026) is uncontroversial. LiteLLM is MIT core (\~60k stars) but open-core: `enterprise/` is BerriAI-licensed, and v1.82.7/1.82.8 suffered a PyPI supply-chain compromise on 24 Mar 2026 — pin versions, verify hashes, never auto-upgrade. Start with the LiteLLM *Python SDK Router in-process*, not the separate proxy server, until you need multi-service keys/budgets.
4. **MCP — KEEP the 2026-07-28 spec, BUILD on FastMCP.** MCP is now the standard tool transport. Use PrefectHQ/fastmcp (\~28k stars, Apache-2.0) to expose Helios tools, and the official MCP Python SDK as the client. Do not build a bespoke JSON-RPC layer.
5. **Security — KEEP RLS, IMPROVE OpenFGA, DEFER Keycloak for v0.1.** RLS is free, native, and the only layer that survives an app bug — implement it from day one with `FORCE RLS`. OpenFGA is correct for the three-scope model but is a second service + dual-write problem; implement scope checks in the app + RLS in v0.1 and add OpenFGA when a second tenant or cross-tenant sharing ships. Keycloak (\~37k stars, Apache-2.0, v26.8.1, 13 Oct 2026) is the right long-term IdP but a Java/Quarkus service that is overkill for a single-tenant v0.1 — start with FastAPI JWT + a thin auth module behind an `AuthProvider` interface, swap in Keycloak at first paying tenant.
6. **Deployment — KEEP Docker Compose, on Hetzner, via Coolify or Kamal.** No K8s in v0.1 is correct. Cheapest honest path: 1× Hetzner CX22 (\~€4.49/mo ex-VAT post-June-2026 hike, 2 vCPU/4 GB/40 GB/20 TB) + Docker Compose + Coolify (Apache-2.0, \~64k stars) for a dashboard, or Kamal (MIT, \~14.6k stars) if you want config-in-git and no control plane. Fly.io and Railway have *no usable free tier in Nov 2026* — do not budget $0 there.
7. **Observability — IMPROVE: OTel from day one, Langfuse self-hosted, NOT Phoenix as a hosted service.** Emit OpenTelemetry GenAI spans everywhere; that instrumentation outlives any backend choice. Langfuse self-hosted (MIT core, \~35k stars, acquired by ClickHouse 16 Jan 2026, no licence change announced) is the $0 backend. Phoenix is Elastic License 2.0 (source-available, bars hosted resale) — usable self-hosted for internal use, but do not build a customer-facing service on it. Opik (Apache-2.0, \~21k stars) is the cleanest-licence alternative if Langfuse's `ee/` split worries you.
