**Scope only:** storage, temporal, graph. **Date:** 14 Nov 2026 (IST). **User:** Vedant Swami, NITK — Helios Signal v0.1, Python modular monolith.\
**ChatGPT baseline audited:** PostgreSQL + pgvector canonical, typed relational edges (no dedicated graph DB yet), object-storage abstraction, 6 contracts, 4 timestamps + valid_from/valid_to, bitemporal, provenance.

## Executive verdict (one paragraph per layer)

1. **Canonical store — KEEP Postgres 18 + pgvector.** Correct choice, and the strongest part of the ChatGPT design. Postgres 18 (25 Sep 2025, EOL 14 Nov 2030) + pgvector 0.8.7 (1 Oct 2026, \~23.5k★, PostgreSQL Licence) gives one transactional store for relational + vector + full-text, with HNSW + iterative scans fixing the filtered-search trap. Do **not** chase Postgres 19 (RC 15 Oct 2026) or a dedicated vector DB at v0.1.
2. **Graph — KEEP typed relational edges; do NOT add a graph DB at v0.1.** Every viable dedicated graph DB in Nov 2026 is either dead (Kuzu, archived 10 Oct 2025), copyleft (Neo4j CE GPLv3), or source-available-not-open-source (FalkorDB SSPL, Memgraph / ArangoDB / SurrealDB BSL 1.1). The only permissive live options — LadybugDB (MIT, Kuzu fork, \~1.4k★) and ArcadeDB / HelixDB (Apache-2.0, \~1.2k★ / \~6.2k★) — are too young / small to bet the canonical store on. Typed edges in Postgres + recursive CTEs + NetworkX/rustworkx offline is the right v0.1 shape; add a graph engine only behind the storage abstraction, gated by a benchmark.
3. **Temporal — IMPROVE, don't just KEEP.** "4 timestamps + valid_from/valid_to" as described is **half a bitemporal design**. Postgres has **no native SQL:2011 system-versioning**; you must implement it yourself (tstzrange + GiST exclusion + append-only + as-of views + a leakage test), or the "point-in-time correctness" claim is false. XTDB 2.x is the only engine that gives bitemporality natively — but it is JVM/Clojure, \~2.9k★, no pgvector, and a second canonical store. Keep Postgres as canonical; **benchmark XTDB as a sidecar, do not adopt it as canonical at v0.1**.
4. **Object storage — REPLACE the MinIO default.** MinIO Community is **dead**: repo archived 25 Apr 2026, last release Oct 2025, Docker Hub images deleted 11 Sep 2026, CVE-2026-39414 fixed only in proprietary AIStor. The abstraction is right; the default backend must change to **SeaweedFS (Apache-2.0, \~35k★, v4.53, 8 Nov 2026) for production self-host, or local filesystem / S3 for v0.1**. RustFS (Apache-2.0, \~35k★, 1.0 GA 16 Sep 2026) is the closest MinIO drop-in but is 2 months past GA with \~30 CVEs in 2026 — evaluate, don't default to it yet. Garage (AGPL-3.0, \~4.9k★) only if geo-distribution matters.
5. **Local dev / analytics — KEEP SQLite for dev, ADD DuckDB as an analytics sidecar (not canonical).** SQLite 3.54.1 (16 Oct 2026, public domain) is the correct $0 dev mirror. DuckDB 2.0 LTS (21 Oct 2026, MIT, \~43k★) is the correct $0 analytical engine for Parquet/exports/benchmarks — but its `vss` vector index is experimental and its DuckPGQ graph extension has no build for 1.5.5+, so it is **not** a replacement for Postgres.

## Cross-cutting: what ChatGPT got right, what it missed, and the decision log to write

### Got right (do not relitigate)

- **One canonical store (Postgres + pgvector)** instead of Postgres + a vector DB + a graph DB + a cache. Every additional store is a consistency, backup, and licence problem.
- **Typed edges, not a graph DB yet.** The graph-DB licence landscape in Nov 2026 (Kuzu dead; Neo4j GPLv3; FalkorDB SSPL; Memgraph/Arango/Surreal BSL) vindicates this — there is no permissive, mature, embedded graph DB to adopt without regret.
- **Object-storage abstraction** (S3 API) instead of bytes in Postgres. Postgres is for facts and pointers; blobs belong in object storage.
- **Bitemporal ambition.** The product's moat *is* "what did we believe, when, and what changed" — getting time right is not a nice-to-have.

### Missed / under-specified (fix before building)

1. **Bitemporality was named, not designed.** "4 timestamps" without an exclusion constraint, append-only rule, as-of function, and leakage test is a *claim*, not a guarantee. See Temporal row — this is the #1 fix.
2. **pgvector's filtered-search trap was not named.** Without `iterative_scan`, every filtered vector query (which is every Helios query — "as of date X, for person Y") silently under-returns. One `SET LOCAL` line + a CI recall test fixes it.
3. **MinIO is dead and was the assumed default in most 2025 material.** Any doc/compose that says MinIO is now a landmine (archived Apr 2026, images deleted Sep 2026, unpatched CVE).
4. **Kuzu is dead; its successors were not named.** LadybugDB (MIT) is the only live permissive embedded graph DB; ArcadeDB/HelixDB (Apache-2.0) are the only live permissive server graph DBs. None should be adopted at v0.1 — but the ADR should name them as the promotion candidates, so a future "we need a graph DB" conversation starts from a shortlist, not a fresh search.
5. **No promotion gates.** Every "later" in the design (XTDB, graph DB, pgvectorscale, RustFS) needs a **named trigger + benchmark** (e.g. "2-hop CTE >100 ms at 100k edges", "as-of-as-was >10× slower in Postgres than XTDB", "HNSW > RAM at 5M vectors"). Without triggers, "later" becomes either premature adoption or permanent drift.
6. **No local-dev parity rule.** SQLite-dev and Postgres-canonical will drift unless the same migrations run against both in CI. Write that rule down.

### Suggested ADR entries (one line each — write them, don't just agree with them)

- ADR-STORE-01: Postgres 18 + pgvector 0.8.7 canonical; `halfvec` + HNSW + iterative scans; no dedicated vector DB at v0.1.
- ADR-STORE-02: Typed relational edges canonical; graph DB deferred behind the edge contract; promotion gate = 2-hop CTE benchmark.
- ADR-STORE-03: Bitemporal in Postgres (ranges + exclusion + append-only + as-of function + leakage test); XTDB 2.2 benchmark-gated sidecar, not canonical.
- ADR-STORE-04: Object storage via S3 abstraction, content-addressed keys; default backend SeaweedFS (single-node `weed mini`); MinIO explicitly rejected (archived Apr 2026).
- ADR-STORE-05: SQLite 3.54+ for local dev (same migrations in CI); DuckDB 2.0 LTS for Parquet/analytics exports only.
- ADR-STORE-06: In-service graph compute = rustworkx (Apache-2.0); NetworkX for exploration; igraph GPL-isolated or not at all.
