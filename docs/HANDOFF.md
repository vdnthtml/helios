# Handoff for engineers, reviewers, and coding agents

## Mission

Help build or evaluate an evidence-backed, temporal, cross-domain Information World Model. The first useful output is a narrow, measurable vertical slice—not an internet-scale knowledge system or a polished chatbot.

## Authoritative order

1. Explicit current founder direction and accepted decision records.
2. This repository’s architecture/status documents.
3. Verified primary evidence and reproducible experiments.
4. Proposals and historical notes.

When sources conflict, preserve the conflict and identify it. Do not silently resolve it by choosing the most convenient implementation.

## Required capability envelope

The architecture must accommodate authorized acquisition, source preservation, extraction, identity uncertainty, typed assertions and events, temporal lineage, scoped memory, evidence-aware retrieval, hypothesis comparison, expert-framework reasoning, historical replay, forecasting, outcome evaluation, controlled learning, and permission boundaries. A narrow MVP may implement each minimally.

## First implementation target

Choose a small, dense, authorized historical corpus. Demonstrate: (1) raw observations; (2) candidate structured records with provenance; (3) reversible identity decisions; (4) a query-specific evidence trail; (5) a historical cutoff replay; (6) a forecast committed before scoring; and (7) an error/cost report.

## Research posture

Use primary documentation, repository code, licenses, reproducible tests, and cited papers when evaluating a technology. Record dates and limitations. Do not describe a tool’s advertised feature as verified integration suitability. Compare against a baseline; reject complexity that cannot improve a stated M0 requirement.

## Questions to resolve before substantial build-out

- What is the first ecosystem, user, decision workflow, and permitted dataset?
- What minimal canonical object and bitemporal contracts make replay possible?
- What independent-source model prevents syndication from looking like corroboration?
- What identity workflow supports review and reversible merges?
- Does segmented retrieval or evidence capsules improve quality/cost over baselines?
- What forecast task, metrics, and anti-leakage protocol are credible?
- Which rights, retention, workspace, and audit controls are mandatory for the pilot?

## Definition of honest progress

Call something implemented only when a reviewer can find its code, contracts, tests, and actual verification results. Otherwise label it as direction, requirement, proposal, research, or open question.
